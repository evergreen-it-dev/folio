# Folio on CapRover

[CapRover](https://caprover.com/) is a self-hosted PaaS on Docker Swarm.
[`folio.yml`](folio.yml) is a [One-Click App](https://github.com/caprover/one-click-apps)
(format `captainVersion: 4`): Folio, PostgreSQL and Redis, one persistent
volume for Folio and one for the database, secrets generated by CapRover.

**You need:** a CapRover instance (v1.12 or newer, for WebSocket support in
one-click apps) with a root domain, and 2 GB of RAM or more.

## Install

1. In CapRover go to **Apps** > **One-Click Apps/Databases**.
2. Choose **>> TEMPLATE <<** at the bottom of the list
   ([how CapRover says to test an app](https://github.com/caprover/one-click-apps#test-your-one-click-apps)),
   paste the whole of [`folio.yml`](folio.yml), and press **Next**.
3. Give the app a name (for example `folio`). The database password and the
   Folio secret are already filled with generated values. Leave the optional
   fields empty unless you use them. **Deploy**.
4. When the app is up, open it in CapRover, **Enable HTTPS**, then under **App
   Configs** change the environment variable `PUBLIC_URL` from `http://` to
   `https://`, and **Save & Update**. Without that step invitation links and the
   cookies' security flag do not match your address.
5. Open the address. The first account is the administrator.

The app is created with WebSocket support switched on, which real-time editing
needs. If you set the app up by hand, tick **Websocket Support** in its HTTP
settings.

## Settings

| Variable | What it does |
|---|---|
| `PUBLIC_URL` | The address people open, exactly as in the browser, including `https`. |
| `FOLIO_SECRET` | Encrypts saved Git tokens and AI keys. Never change it. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_ALLOWED_DOMAINS` | "Sign in with Google" (optional). |
| `CURSOR_API_KEY` | Shared AI assistant key (optional). |

Edit them under **App Configs** > **Environmental Variables**. The database
password is set when the database is first created; changing it in the app
later does not change it in PostgreSQL.

## Update

Open the app > **Deployment** and set the image name to a newer tag (for
example `ghcr.io/evergreen-it-dev/folio:v0.2.0`), or with `latest` press
**Force Update**. The database migrates itself on start. Back up before.

## Backup

CapRover backs up its own configuration, not your volumes. On the server:

```bash
docker exec $(docker ps -qf name=srv-captain--folio-db.1) pg_dump -U folio folio > folio-db.sql
docker exec $(docker ps -qf name=srv-captain--folio.1) tar czf - -C /app/data . > folio-data.tgz
```

(`folio` is the app name you chose.)

## Limits

- The app waits for no health check; if it starts before PostgreSQL is ready,
  Docker Swarm restarts it, so the first start may show a 502 for a minute.
- The file follows CapRover's documented format but has not been run on a live
  CapRover instance.

## Submitting to the official list

Pull request to [caprover/one-click-apps](https://github.com/caprover/one-click-apps):
`public/v4/apps/folio.yml` plus a logo in `public/v4/logos/`. They ask to run
`npm run validate_apps` and `npm run formatter-write` first. Set
`isOfficial: true` only if the maintainers say so; the image comes from the
project's own registry, not Docker Hub.

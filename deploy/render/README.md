# Folio on Render

[Render](https://render.com/) builds the whole stack from one Blueprint file:
the app from the published image, a PostgreSQL database, a Key Value
(Redis-compatible) instance and a persistent disk.

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/evergreen-it-dev/folio)

The button reads [`render.yaml`](../../render.yaml) from the root of the
repository. It works once the repository is public and the image
`ghcr.io/evergreen-it-dev/folio` is published and public.

## What it costs, and why not free

Folio keeps the Git repositories of your spaces on disk, and **Render offers a
persistent disk only on paid web service plans**
([Render: persistent disks](https://render.com/docs/disks)). So the blueprint
uses a paid plan, and there is no free-tier variant that keeps your pages.

| Resource | Plan in the blueprint | Why |
|---|---|---|
| Web service | `standard` (2 GB RAM) | The app idles near 450 MB; `starter` (512 MB) is too tight. Edit the plan to `starter` only for a trial. |
| Disk | 10 GB at `/app/data` | Git repositories and uploads. Can grow, never shrink. |
| PostgreSQL | `basic-256mb`, 5 GB | The database holds the index and access rights, not your only copy of the pages. |
| Key Value | `free` | Transient data only. |

See Render's [pricing](https://render.com/pricing) for the current prices.

## Install

1. Click **Deploy to Render** (or **New** > **Blueprint** and choose the repository).
2. Render asks for `PUBLIC_URL`. Type the address the service will have:
   `https://folio.onrender.com` (the service name is `folio`; if the name is
   taken Render adds a suffix, so check the real address on the service page and
   correct `PUBLIC_URL` under **Environment** afterwards). With a custom domain,
   use that.
3. Leave the Google and Cursor values empty unless you use them. **Deploy Blueprint**.
4. When the service is **Live**, open it. The first account is the administrator.

`FOLIO_SECRET` is generated by Render and kept (it encrypts saved Git tokens
and AI keys; never change it). The database and Key Value connection strings
are wired in automatically over Render's private network.

## Update

The blueprint uses the `latest` image. Press **Manual Deploy** > **Deploy latest
reference**, or change the image tag in the service's settings (pin `v0.1.0` to
update on your terms). A service with a disk stops the old instance before it
starts the new one, so an update means a short downtime
([zero-downtime deploys are off with a disk](https://render.com/docs/disks)).

## Backup

- **Database:** Render Postgres has its own backups (paid plans); or
  `pg_dump "<external connection string>" > folio-db.sql` from your machine.
- **Disk:** Render takes daily disk snapshots you can restore from the
  dashboard. For a copy of your own, open a shell on the service
  (**Shell** tab) and run `tar czf - -C /app/data .` into a file you download.

## Limits

- One instance only: a service with a disk cannot be scaled to several.
- WebSocket (real-time editing) is supported by Render's web services.
- The blueprint file has been checked against Render's published
  [JSON schema](https://render.com/schema/render.yaml.json), but not deployed in
  a real Render account yet. Please tell us what differs.
